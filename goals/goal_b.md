請直接開始，做到完，不要停下來問我。需要選擇的地方，一切皆採建議值。這份文件就是全部的指示。

【目標】
和上一次同樣的話：「今天想吃什麼」，最後也補了同一句：「媽媽這餐打算帶一千去買菜，這頓也不一定要煮完」。一樣交 shopping.md、menu.json、menu.html，這一次放在 runs/b，格式照 spec.md。你是主廚：你規劃、派工、跑關卡、寫紀錄。菜單不是你寫的。

【分工】
把工作派給三個 subagent。一個角色一個模型、一種 effort（想多深）。角色檔已經在專案裡：
- shopper（採購）：大模型，effort 中。只寫 shopping.md。要替使用者判斷的事，多半在這一步。
- recipe（食譜）：中模型，effort 中。讀 shopping.md，寫 menu.json 和 menu.html。
- inspector（驗收，在旁邊看的人）：小模型，effort 低。只能讀，不能改任何檔案。它便宜，所以每一輪都叫得起。
派工時用角色檔的名字（shopper、recipe、inspector）派，模型和 effort 照角色檔，不要自己另外選模型。
交代工作時，把資料夾、這份文件的【規則】、第五條品味一起告訴它。它看不到我們的對話。
派出去 3 分鐘還沒有檔案，就中斷它，照角色檔的名字再派一次。還是不行，或你的工具派不出 subagent，才改用下面這一行替那個角色叫人，一次一個角色，並在 log.md 寫明。這一行也連續兩次沒成功（Codex 在自己的沙盒裡叫不動 Codex），那個角色的檔案就由你照 cards/b_（角色）.md 自己寫，並在 log.md 的「派工」寫明「這一步是主廚代做的」。不要因為這樣停下來。--tool 後面寫你自己這一家：claude、codex、agy、copilot 其中一個。
python3 tools/ask.py --tool claude --role shopper --name b --say "今天想吃什麼（最後補了一句：媽媽這餐打算帶一千去買菜，這頓也不一定要煮完）"
--say 後面只放使用者那一句話，照上面那一行，一個字都不要加。要多交代的事（這一輪要改什麼）寫進 runs/b/fix.md，用 --feedback 交過去。
叫 inspector 時，在這一行最後加上 --round 和這一輪的號碼（第 1 輪寫 --round 1），它的回答才不會蓋掉上一輪的。要它照沒過的那幾行改時，先把那幾行寫進 runs/b/fix.md，再在這一行最後加上 --feedback runs/b/fix.md。

【品質標準與品味】
品質標準和上一次一樣：一位台灣的媽媽拿著這張清單去市場，照著買、照著煮，孩子吃得開心。合格一樣是兩層：關卡全綠，而且品味 8 分以上（滿分 10，五條：前四條在 taste.md；第五條是：要有一道孩子會搶著吃的菜）。
不一樣的是：品味不再由做菜的人自己評。每一輪都交給 inspector 評分，它的回答原樣存成 runs/b/review_r1.md、review_r2.md，以此類推。你和 recipe 都不能改它的分數。存檔前先看第一行是不是「品味：N/10」；不是，請驗收照格式重寫一次，你不要自己改。
透過自我檢查，反覆自行提升品質，直到達到該品質標準為止。

【自我檢查】
每一輪，inspector 除了評品味，也用使用者的眼睛答三題（寫在它的角色檔裡）：這個價錢我憑什麼相信？這頓真的煮得完、吃得完嗎？有哪個決定是做菜的人替使用者做的？
答不出來的，就是下一輪要補的：交給該補的那個角色。

【工具】
動手做每一步之前，先判斷這一步屬於哪一種：
- 要算得準、要比對、或之後每一輪都會重做的事（例如加總價錢、核對採購清單和菜單有沒有對上）：先寫成一支小程式放在 mytools/，以後每一輪都執行它，不要用心算或目測。
- 需要判斷和品味的事（例如這桌菜孩子會不會喜歡）：你自己判斷，不要做成程式。

這樣做是因為：同一件事每一輪都用同一支程式檢查，結果才穩定，我事後也才能重跑一次確認。
做了哪些工具、為什麼做，寫進每一輪的紀錄。現成的關卡 tools/check.py 不能改。

【規則】
- 不要讀 runs/a 裡的檔案（兩次的比較交給 tools/compare.py）。
- 不要打開、不要修改 tools/ 裡的任何檔案，也不要改 spec.md 和 taste.md。
- 不要用 inputs/ 裡的檔案：那是另一個任務的材料，不是這一家的冰箱。
- 不要跳步驟：先有 shopping.md，才寫 menu.json。
- 不要為了過關，把一桌菜變得不像一頓飯。那是走捷徑，不算過關。
- 關卡已經綠燈的版本，不要為了品味改成紅燈。兩邊衝突時，在紀錄寫明，並以關卡綠燈的那一版交件：那一版的三個檔案，關卡已經備份在 runs/b/round（輪數）/ 裡，不用自己搬回來，回報時寫明是第幾輪。
- 只有 shopper 寫 shopping.md，只有 recipe 寫 menu.json 和 menu.html，inspector 什麼都不寫（只有上面說的「主廚代做」是例外）。你自己只寫 log.md、review 檔、fix.md 和 mytools/ 裡的小程式。
- 寫檔用你的寫檔工具，不要用 shell 的 cat、echo 或 << 寫檔。只寫 runs/b 和 mytools/ 裡的檔案（tools/compare.py 會自己更新 eval.md，這個除外）。

【關卡】
由你執行，不是 subagent。指令照抄，前後不要加別的東西（只有一個例外：Windows 把 python3 換成 py）：
python3 tools/round.py runs/b --max 3
用法和上一次一樣：開工前先跑一次當起點，之後每輪一次。紅燈時，只把 [FAIL] 的那幾行交給該修的角色。第一行 GUARD 不是 OK 時，就算沒有 [FAIL]，也要在紀錄寫明它說了什麼；它說 tools/、spec.md 或 taste.md 被改過，就停下來回報，不要自己修。綠燈之後的那一輪，把驗收最不滿意的那一條，或三題裡答不出來的那一題，交給該修的角色。

【每一輪的紀錄】
runs/b/log.md：第一行先寫「第五條品味：」加上第五條的內容（驗收會讀這一行）。之後每跑完一次關卡（起點不算），在最後加一段，格式固定：

關卡：（把 ROUND 那一行原樣貼上，例如 ROUND: 1/3 RED (6/8)，一個字都不要改）

【停止】
- 關卡第一次綠燈之後，至少再做一輪：改品味最弱的那一條，或三題裡答不出來的那一題，關卡要保持綠燈；真的改不動，在紀錄寫明為什麼。
- 做完這一輪，關卡綠燈、inspector 給 8 分以上，而且三題都答得出來：停。最多 3 輪；跑滿還沒到，也要停：列出還沒過的項目，各寫一句卡在哪裡。
- 停下來之後，執行 python3 tools/compare.py，把印出來的表貼給我，再用三句話說：和 runs/a 比，輪數、通過幾項、花的時間、價錢有出處的有幾個、記了幾個岔路，各是變好、變差還是一樣。
- 「值不值得分工」這個結論留給我自己寫，你不要寫。
