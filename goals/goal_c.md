這一次沒有那一句話，只有兩樣材料：inputs/fridge.png（一張冰箱的圖）和 inputs/recipe_en.txt（一份英文食譜）。使用者最後補了一句：「媽媽這餐打算帶一千去買菜，這頓也不一定要煮完」。請用冰箱裡有的東西，做出一桌四道菜的午餐，其中一道照那份食譜做。交 shopping.md、menu.json、menu.html，放在 runs/c，格式照 spec.md。

【三家分工】
你是主對話：你計劃、管理、安排工具，並且寫出任務佈局。下面三件事不要自己做，交給別家：
- 看圖、翻譯：Google Gemini（工具名是 agy）。
- 設計菜單那一頁（menu.html）：Codex。
- 驗收，當另一雙眼睛：Google Gemini（agy）。
叫別家只用這一種指令，一次一件事，前後不要加別的東西：
python3 tools/ask.py --tool agy --card cards/see.md --image inputs/fridge.png --name c
python3 tools/ask.py --tool agy --card cards/translate.md --name c
python3 tools/ask.py --tool codex --card cards/design.md --name c
python3 tools/ask.py --tool agy --card cards/review.md --name c --round 1
（Windows 把 python3 換成 py。）--round 後面寫這一輪的號碼：第 1 輪寫 1，第 2 輪寫 2。它印 ASK: OK 加檔案位置，才算成功；印別的就是沒成功。要設計的那一家照沒過的那幾行改 menu.html 時，先把那幾行寫進 runs/c/fix.md，再在那一行最後加上 --feedback runs/c/fix.md。同一家連續兩次沒成功，就把 --tool 換成另一家。別家都叫不動，才換成你自己這一家，並在 plan.md 和 log.md 寫明「這一步是同一家做的」。不要自己偷偷代做。

【步驟】
1. 先跑一次關卡當起點（指令在【關卡】），一定是紅燈。
2. 寫 runs/c/plan.md，這是任務佈局：每一步的輸入、誰做、輸出、怎麼檢查。再在 runs/c/log.md 第一行寫「第五條品味：」加上第五條的內容。
3. 叫別家做出 runs/c/fridge.md 和 runs/c/recipe_zh.md。拿到後自己核對：fridge.md 每行一個食材；recipe_zh.md 的份量、時間和原文一樣。不對就請同一家重做，最多一次。
4. 你自己寫 shopping.md（冰箱已經有的寫 0 元，依據寫「冰箱已有」）和 menu.json。
5. 叫別家設計 menu.html。
6. 每一輪都要做三件事：跑關卡、叫別家驗收（紅燈那一輪也要）、寫紀錄。照【停止】決定要不要再一輪。改了 menu.json（例如換一道菜），要先請設計的那一家照新的 menu.json 重做 menu.html，兩個檔案對上了，再跑關卡。

【自我檢查】

【工具】
動手做每一步之前，先判斷這一步屬於哪一種：
- 要算得準、要比對、或之後每一輪都會重做的事（例如加總價錢、核對採購清單和菜單有沒有對上）：先寫成一支小程式放在 mytools/，以後每一輪都執行它，不要用心算或目測。
- 需要判斷和品味的事（例如這桌菜孩子會不會喜歡）：你自己判斷，不要做成程式。

這樣做是因為：同一件事每一輪都用同一支程式檢查，結果才穩定，我事後也才能重跑一次確認。
做了哪些工具、為什麼做，寫進每一輪的紀錄。現成的關卡 tools/check.py 不能改。
